Capital Bikeshare — 次日租赁量预测

NUS ISS Assignment · UCI Bike Sharing Dataset (2011–2012) · MLOps experiment tracking demo

1. 问题

运营团队需要在每晚估计次日总租赁量，用于排班与车辆调度。估计太低会对高峰日准备不足，太高则增加运营成本。因此只能使用当晚可得的信息预测明天，并与朴素基准对比：明天 = 昨天。

2. 方法

  • 时间切分：2011 全年训练（358 天），2012 全年测试（366 天），不 shuffle，杜绝未来信息泄漏。
  • 泄漏防护：丢弃 casual、registered（二者之和即目标 cnt）。
  • 合法特征：lag1（昨天，昨晚已知）、lag7（上周同日）、weathersit（天气状况）。
  • 两个分析师：A = 纯自回归 AR(1)（仅 lag1）；B = 加入周滞后 + 天气状况。均为 Ridge 回归（纯 numpy 实现，含 drop-first 独热与 z-score 标准化）。
  • 可追溯（MLflow）：每次运行用 mlflow.log_params / log_metrics / set_tag / log_input 记录数据时段、特征、参数、指标与标签；最佳模型通过 mlflow.register_model 注册为命名版本 BikeShareForecaster（当前 v2）。

3. MLflow 实验追踪与模型注册

本地用 sqlite:///mlflow.db 作为 tracking store，实验名为 CapitalBikeshare。两次 run 的参数/指标/标签全部入库，最佳模型已注册到 Model Registry。查看方式：

python src/train.py      # 跑实验并记录到 MLflow
mlflow ui                # 打开 http://127.0.0.1:5000 浏览 runs 与注册模型
  • Runs：analystA_ar1、analystB_weather，可对比各自的 RMSE / 特征 / 超参。
  • Model Registry：BikeShareForecaster 已有 v1、v2 两个命名版本，可检索、可复现。

6. 如何复现

python src/train.py
